# 08. Механики match-3

## Модель доски

`Board` хранит сетку `cols × rows`, в каждой клетке либо `Tile | null`.
У `Tile` есть `id` (стабильный во времени), `type` (цвет), `col`, `row`.

```ts
interface TileModel {
  id: number;
  type: number;
  col: number;
  row: number;
}
```

`id` ключевой: он позволяет связать модель с view-объектом и анимировать
тайл через любые изменения позиции.

## Операции доски

- `swap(a, b)` — мгновенный своп в модели.
- `remove(positions[])` — удалить тайлы в указанных клетках (поставить null).
- `collapse()` — гравитация: тайлы падают вниз, заполняя null. Возвращает
  список перемещений `{ id, from, to }`.
- `refill()` — создание новых тайлов сверху. Возвращает массив новых
  `TileModel`.
- `generateInitial()` — генерация стартовой доски без начальных матчей.

Все операции **мутируют** модель. Это сознательное решение: доска
большая, а реактивности на каждой клетке у нас нет. Реактивная
прослойка живёт в `useAppStore` и публикуется через `EventBus`.

## Поиск совпадений

### Линии (`findMatches`)

Ищет горизонтали и вертикали длиной ≥ 3 из **обычных** цветов
(`type < TILE_TYPES`), объединяет пересекающиеся горизонталь+вертикаль
в группу `kind: 'cross'`.

### Квадраты 2×2 (`findSquareMatches`)

Ищет блоки 2×2 из четырёх **обычных** тайлов одного цвета — основа для
**ракеты** (самолётика).

### Сводка для каскада (`collectMatchGroups`)

`matchFinder.collectMatchGroups(board)` = `findMatches(board)` +
`findSquareMatches(board)` — один вызов на шаг каскада.

```ts
interface MatchGroup {
  tiles: TilePosition[];
  length: number;
  kind: 'row' | 'col' | 'cross' | 'square';
}
```

### Сложность

- Линии: `O(cols * rows)`.
- Квадраты: `O(cols * rows)`.

## Каскад

`cascade.nextCascadeStep(board)`:

1. `groups = collectMatchGroups(board)`; если пусто — `null`.
2. `planBoosterSurvivorsFromMatches(groups)` — какие клетки снести, какие
   превратить в бустер (см. ниже), с учётом **приоритета** при пересечении
   групп (линия ≥5 → крест → линия 4 → квадрат 2×2 → линия 3).
3. Применить апгрейды типов, `remove`, `collapse`, `refill`.

Цикл в `BoardController.resolveCascades()`: pop → обновление спрайтов
апгрейдов → move → spawn.

## Свопы и откаты

- Игрок выбирает первый тайл — выделение масштабом 1.08.
- Если второй тайл смежен:
  1. Своп в модели, анимация.
  2. Если сработал **бустерный своп** (`getBoosterSwapClear` не `null`) —
     ход тратится, каскад по области бустера.
  3. Иначе ищем обычные матчи (`collectMatchGroups`); если пусто —
     откат свопа **без** траты хода.
  4. Иначе — `decrementMove()` и каскад.

## Подсчёт очков

`SCORE_BY_LENGTH` для линий по длине; для `cross` — база как за 5 + бонус
за каждый тайл сверх 5; для `square` — как за линию из 4 (60).
Очки за шаг каскада + `scoreForBoosterClear` при ручной активации бустера.

## Цель уровня и проигрыш

- `target` — порог счёта (1200 по умолчанию).
- `moves` — лимит ходов (25 по умолчанию).
- Победа: `score >= target`.
- Поражение: `moves == 0 && score < target`.

В `useAppStore` это происходит автоматически в `addScore` и `decrementMove`.

Для проверки «есть ли ход» используйте виртуальный своп и

## Бустеры на поле (реализовано)

Спец-типы задаются константами в `constants.ts` (`TILE_TYPE_*`).
В линиях участвуют только обычные цвета; бустеры **не** спавнятся из
`refill`, только появляются из матча или остаются после каскада.

### Создание (после матча, `boosterFromMatch.ts`)

| Условие | Бустер | Примечание |
|--------|--------|--------------|
| Линия ≥ 5 в ряд или столбец | Радужный шар (`TILE_TYPE_COLOR`) | Центр линии |
| Перекрёсток линий (`cross`) | Бомба (`TILE_TYPE_BOMB`) | Типично Т / + из пятёрки |
| Ровно 4 в линии | Стрела: горизонталь (`LINE_ROW`) или вертикаль (`LINE_COL`) | Как ориентация линии |
| Квадрат 2×2 одного цвета | Ракета (`TILE_TYPE_PLANE`) | Угол квадрата как якорь |

При пересечении правил выигрывает более «сильный» вариант (см. приоритет
в `planBoosterSurvivorsFromMatches`).

### Активация свопом с соседом (`boosterActivation.ts`)

Двойной тап **не** реализован — только обмен с соседней клеткой.

- **Стрела** + обычный: направление **строка vs столбец** задаётся
  **направлением свопа** (горизонтальный своп → чистится вся строка,
  вертикальный → весь столбец), позиция — клетка стрелы после свопа.
- **Радужный** + обычный: снос всех тайлов цвета соседа.
- **Бомба** + обычный: взрыв Чебышёва радиуса 1 (квадрат 3×3).
- **Ракета** + обычный: соседи по кресту вокруг ракеты + «удар» по
  дальней клетке (детерминированный выбор среди обычных тайлов) и её
  соседям по кресту.

### Комбо: два бустера рядом

Обмен двух спец-тайлов на соседних клетках (`tryTwoSpecialCombo`):

- Две бомбы — объединённый взрыв радиуса 2 (до 5×5 на каждую центр).
- Две ракеты — три «удара» по дальним клеткам с крестом вокруг каждой.
- Ракета + бомба — эффект ракеты + 3×3 бомбы.
- Две стрелы — две строки, два столбца или крест (стр.+столб.) в
  зависимости от комбинации типов `LINE_ROW` / `LINE_COL`.
- Радужный + бомба / стрела / ракета — снос самого частого обычного
  цвета на доске плюс эффект второго бустера (упрощённый аналог
  «диско + бонус» в коммерческих играх).
- Ракета + стрела, бомба + стрела — объединение их областей.

Своп **двух радужных** — невалиден (как и раньше).

Подробная целевая модель (приоритеты, очередь активаций, комбо, plane targets,
псевдокод и edge cases): **`docs/17-booster-system-architecture.md`**.

## Перемешивание (random seeded)

`Board` принимает `seed`. RNG — `mulberry32` (детерминированный),
что позволяет:

- Воспроизводить “проблемные” доски в тестах.
- Сохранять/делиться seed'ом уровня.
- Гарантировать одинаковый старт для всех клиентов в (будущей) сетевой
  версии.
