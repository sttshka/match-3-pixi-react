# 08. Механики match-3

## Модель доски

`Board` хранит сетку `cols × rows`, в каждой клетке либо `Tile | null`.
У `Tile` есть `id` (стабильный во времени), `type` (цвет), `col`, `row`.

```ts
interface TileModel {
  id: number;
  type: number;
  col: number;
  row: number;
}
```

`id` ключевой: он позволяет связать модель с view-объектом и анимировать
тайл через любые изменения позиции.

## Операции доски

- `swap(a, b)` — мгновенный своп в модели.
- `remove(positions[])` — удалить тайлы в указанных клетках (поставить null).
- `collapse()` — гравитация: тайлы падают вниз, заполняя null. Возвращает
  список перемещений `{ id, from, to }`.
- `refill()` — создание новых тайлов сверху. Возвращает массив новых
  `TileModel`.
- `generateInitial()` — генерация стартовой доски без начальных матчей.

Все операции **мутируют** модель. Это сознательное решение: доска
большая, а реактивности на каждой клетке у нас нет. Реактивная
прослойка живёт в `useAppStore` и публикуется через `EventBus`.

## Поиск совпадений

### Линии (`findMatches`)

Ищет горизонтали и вертикали длиной ≥ 3 из **обычных** цветов
(`type < TILE_TYPES`), объединяет пересекающиеся горизонталь+вертикаль
в группу `kind: 'cross'`.

### Квадраты 2×2 (`findSquareMatches`)

Ищет блоки 2×2 из четырёх **обычных** тайлов одного цвета — основа для
**ракеты** (самолётика).

### Сводка для каскада (`collectMatchGroups`)

`matchFinder.collectMatchGroups(board)` = `findMatches(board)` +
`findSquareMatches(board)` — один вызов на шаг каскада.

```ts
interface MatchGroup {
  tiles: TilePosition[];
  length: number;
  kind: 'row' | 'col' | 'cross' | 'square';
}
```

### Сложность

- Линии: `O(cols * rows)`.
- Квадраты: `O(cols * rows)`.

## Каскад

`cascade.nextCascadeStep(board)`:

1. `groups = collectMatchGroups(board)`; если пусто — `null`.
2. `planBoosterSurvivorsFromMatches(groups)` — какие клетки снести, какие
   превратить в бустер (см. ниже), с учётом **приоритета** при пересечении
   групп (**линия ≥5** → **крест 5–6 (бомба)** → **квадрат 2×2** → **линия 4** → линия 3).
3. Применить апгрейды типов, `remove`, `collapse`, `refill`.

Цикл в `BoardController.resolveCascades()`: pop → обновление спрайтов
апгрейдов → move → spawn.

## Свопы и откаты

- **Свайп** (`BoardController`): `pointerdown` на тайле → жест в сторону соседа; при
  достаточной длине и явной оси — своп с соседом по направлению (CSS `clientX` / `clientY`).
  `pointercapture` на canvas; короткое движение — не своп.
- **Короткий тап** (движение меньше порога) по ракете, бомбе или самолётику —
  `getBoosterTapClear` (комбо двух бустеров — свайп одного на соседа с другим бустером).
- После успешного свопа:
  1. Своп в модели, анимация.
  2. Если оба тайла — **радужные шары** — `applyRainbowDuoClearAndGravity`: снос всех
     фишек; у клеток с `TileModel.obstacleLayers` снимается один слой.
  3. Иначе если сработал **бустерный своп** (`getBoosterSwapClear` не `null`) —
     ход тратится, каскад по области бустера.
  4. Иначе ищем обычные матчи (`collectMatchGroups`); если пусто —
     откат свопа **без** траты хода.
  5. Иначе — `decrementMove()` и каскад.

## Подсчёт очков

`SCORE_BY_LENGTH` для линий по длине; для `cross` — база как за 5 + бонус
за каждый тайл сверх 5; для `square` — как за линию из 4 (60).
Очки за шаг каскада + `scoreForBoosterClear` при ручной активации бустера.

## Цель уровня и проигрыш

- `target` — порог счёта (1200 по умолчанию).
- `moves` — лимит ходов (25 по умолчанию).
- Победа: `score >= target`.
- Поражение: `moves == 0 && score < target`.

В `useAppStore` это происходит автоматически в `addScore` и `decrementMove`.

## Анти-deadlock и валидные ходы (опционально, см. TODO)

Для проверки «есть ли ход» используйте виртуальный своп и
`collectMatchGroups` (или минимум `findMatches`, если препятствий нет).

## Бустеры на поле (реализовано)

Спец-типы задаются константами в `constants.ts` (`TILE_TYPE_*`).
В линиях участвуют только обычные цвета; бустеры **не** спавнятся из
`refill`, только появляются из матча или остаются после каскада.

### Создание (после матча, `boosterFromMatch.ts`)

| Условие | Бустер | Примечание |
|--------|--------|--------------|
| Линия ≥ 5 в ряд или столбец | Радужный шар (`TILE_TYPE_COLOR`) | Только для групп `row` / `col`, центр линии |
| Перекрёсток линий (`cross`), ровно **5 или 6** клеток | Бомба (`TILE_TYPE_BOMB`) | Г / Т / + |
| Ровно 4 в линии | Ракета: `LINE_COL` (горизонталь 4 → столбец) или `LINE_ROW` (вертикаль 4 → строка) | Как ориентация линии |
| Квадрат 2×2 одного цвета | Бумажный самолётик (`TILE_TYPE_PLANE`) | Угол квадрата как якорь |

При пересечении правил выигрывает более «сильный» вариант (см. приоритет
в `planBoosterSurvivorsFromMatches`).

### Активация (`boosterActivation.ts`)

- **Ракета, бомба, самолётик** — одно нажатие по клетке (`getBoosterTapClear`), без свопа.
- **Радужный** — только своп с соседней обычной фишкой: снос всех тайлов этого цвета.
- **Ракета** + обычный (своп): полная строка или столбец по **типу** ракеты; самолётик —
  крест вокруг себя, удар по цели (приоритет: `isGoal`, затем `obstacleLayers`, затем остальные)
  и крест вокруг цели.

### Комбо: два бустера рядом

Своп двух спец-тайлов на соседних клетках (`tryTwoSpecialCombo` + цепочка `expandBoosterChain`):

- **Две бомбы** — один центр между ними, Чебышёв радиус **2** (удвоенный радиус бомбы).
- **Бомба + ракета** — три полных столбца, затем три полные строки шириной в три клетки
  вокруг центра пары (`threeRowsThreeColsBand`).
- **Две ракеты** — одна полная строка и один полный столбец.
- **Самолётик + бомба / ракета** — как обычный самолётик, затем бомба / полоса **в клетке цели** самолётика.
- **Два самолётика** — один полный самолётик с первой позиции пары, затем три волны самолётика
  из центра между бустерами.
- **Радужный + бомба / ракета / самолётик** — все клетки самого частого обычного цвета плюс
  эффект второго бустера с каждой такой позиции.
- **Два радужных** — см. `applyRainbowDuoClearAndGravity` (очистка поля и слой с препятствий).

Подробная целевая модель: **`docs/17-booster-system-architecture.md`**.

## Перемешивание (random seeded)

`Board` принимает `seed`. RNG — `mulberry32` (детерминированный),
что позволяет:

- Воспроизводить “проблемные” доски в тестах.
- Сохранять/делиться seed'ом уровня.
- Гарантировать одинаковый старт для всех клиентов в (будущей) сетевой
  версии.
