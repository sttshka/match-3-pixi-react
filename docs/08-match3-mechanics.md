# 08. Механики match-3

## Модель доски

`Board` хранит сетку `cols × rows`, в каждой клетке либо `Tile | null`.
У `Tile` есть `id` (стабильный во времени), `type` (цвет), `col`, `row`.

```ts
interface TileModel {
  id: number;
  type: number;
  col: number;
  row: number;
}
```

`id` ключевой: он позволяет связать модель с view-объектом и анимировать
тайл через любые изменения позиции.

## Операции доски

- `swap(a, b)` — мгновенный своп в модели.
- `remove(positions[])` — удалить тайлы в указанных клетках (поставить null).
- `collapse()` — гравитация: тайлы падают вниз, заполняя null. Возвращает
  список перемещений `{ id, from, to }`.
- `refill()` — создание новых тайлов сверху. Возвращает массив новых
  `TileModel`.
- `generateInitial()` — генерация стартовой доски без начальных матчей.

Все операции **мутируют** модель. Это сознательное решение: доска
большая, а реактивности на каждой клетке у нас нет. Реактивная
прослойка живёт в `useAppStore` и публикуется через `EventBus`.

## Поиск совпадений

`matchFinder.findMatches(board)` ищет линии длиной ≥ 3:

1. Сканирует горизонтали — последовательности тайлов одного типа.
2. Сканирует вертикали — то же самое.
3. Объединяет пересекающиеся горизонталь+вертикаль в **`cross`**
   (чтобы не учитывать пересечение дважды).

Возвращает массив `MatchGroup`:

```ts
interface MatchGroup {
  tiles: TilePosition[];
  length: number;
  kind: 'row' | 'col' | 'cross';
}
```

### Сложность

- Время: `O(cols * rows)` — линейное.
- Память: пропорциональна количеству групп. Для 8×8 это микроскопические
  числа, можно делать каждый кадр без оптимизаций.

## Каскад

```ts
function nextCascadeStep(board) {
  const groups = findMatches(board);
  if (groups.length === 0) return null;
  const removed = groups.flatMap(g => g.tiles);
  board.remove(removed);
  const moves = board.collapse();
  const spawned = board.refill();
  return { resolved: { groups, scoreGained, removed }, moves, spawned };
}
```

Цикл каскада в `BoardController.resolveCascades()`:

1. `step = nextCascadeStep(board)`.
2. Если `null` — каскад окончен.
3. Иначе: обновить счёт, анимировать pop → move → spawn.
4. Повторить.

## Свопы и откаты

- Игрок выбирает первый тайл — выделение масштабом 1.08.
- Если второй тайл смежен — выполняется флоу:
  1. Свопаем в модели.
  2. Анимируем позиции через GSAP.
  3. Ищем матчи.
  4. Нет матчей → откатываем свап в модели + анимируем обратно
     (трата хода НЕ происходит).
  5. Есть матчи → `decrementMove()` + каскады.

Это классическая механика — нельзя “потратить” ход на бесполезный свап.

## Подсчёт очков

`SCORE_BY_LENGTH` задаёт шкалу:

- 3 совпавших — 30
- 4 — 60
- 5 — 120
- 6+ — 200 + бонусы

Для `cross` берётся фиксированная база (как за 5), плюс бонус за каждый
тайл сверх 5.

Очки начисляются на **каждом** шаге каскада. Игрок, который запустил
длинный каскад, получает аккумулятивную награду — это базовая
геймплейная петля match-3 с “комбо-чувством”.

## Цель уровня и проигрыш

- `target` — порог счёта (1200 по умолчанию).
- `moves` — лимит ходов (25 по умолчанию).
- Победа: `score >= target`.
- Поражение: `moves == 0 && score < target`.

В `useAppStore` это происходит автоматически в `addScore` и `decrementMove`.

## Анти-deadlock и валидные ходы (опционально, см. TODO)

Чтобы избежать ситуации “нет ни одного валидного хода”:

1. После каскада сканируйте доску: для каждой пары соседей делайте
   виртуальный своп и `findMatches`. Если хоть один свап даёт матч —
   доска валидная.
2. Если ни один — запустите анимацию “перемешивания”: перетасуйте
   `type` тайлов, пока валидный ход не появится.

## Бустеры (опционально)

- **Бомба 3×3** — особый `type`. Активация удаляет 9 клеток вокруг.
- **Линейный** — удаляет всю строку/столбец.
- **Цветной** — удаляет все тайлы выбранного цвета.

Реализация:

1. Добавить `Tile.kind: 'normal' | 'bomb' | 'line' | 'colorBomb'`.
2. В `findMatches` распознавать длинные группы (≥4, ≥5) и в `cascade`
   на месте таких групп создавать бустер вместо обычного спавна.
3. При активации (своп с бустером) — вызывать соответствующую функцию
   разрушения и добавлять очки.

## Перемешивание (random seeded)

`Board` принимает `seed`. RNG — `mulberry32` (детерминированный),
что позволяет:

- Воспроизводить “проблемные” доски в тестах.
- Сохранять/делиться seed'ом уровня.
- Гарантировать одинаковый старт для всех клиентов в (будущей) сетевой
  версии.
