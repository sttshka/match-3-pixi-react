# 03. Архитектура

## Принципы

1. **Доменная логика — чистая.** `Board`, `matchFinder`, `cascade`, `gameMachine`
   написаны без зависимостей от Pixi, React и DOM. Их можно тестировать
   в Node без всяких моков.
2. **React владеет UI, Pixi владеет сценой.** Точка пересечения — компонент
   `<Application>` из `@pixi/react`. Внутри живут либо декларативные `pixi*`
   элементы, либо ref на корневой `Container`, в который мы императивно
   собираем игру.
3. **Слабая связность через `EventBus`.** Игровые события (`matches:found`,
   `swap:invalid`, `cascade:step`) транслируются в шину; звук, UI и
   аналитика подписываются и реагируют независимо.
4. **Последовательные действия — через `CommandQueue`.** Любая длительная
   операция (анимация свопа, каскад) кладётся в очередь как
   `() => Promise<void>`; следующая команда запускается строго после
   завершения предыдущей.
5. **Расширяемость > преждевременная оптимизация.** Внутренние API
   намеренно простые, чтобы их можно было заменять без рефакторинга
   соседних слоёв.

## Потоки данных

### Кадр (tick)

```
Application
   └── Ticker.tick (60 FPS)
         ├── useGameTick → physics.step(deltaMS)
         ├── GSAP-tweens (используют свой внутренний raf)
         └── Pixi рендер сцены
```

### Игровое действие (свайп/тап)

```
User pointerdown ──▶ BoardController.onPointerDown
                     │ если первый тап — выделить
                     │ если adjacent — попытка свопа
                     ▼
                     CommandQueue.push(async swapFlow)
                     │   ▶ Board.swap(a, b)             (модель)
                     │   ▶ animateSwap(...)             (GSAP)
                     │   ▶ collectMatchGroups(board)  (логика каскада)
                     │   ├─ если пусто → откатить swap, анимировать
                     │   └─ если есть → resolveCascades():
                     │        loop:
                     │          step = nextCascadeStep(board)
                     │          score += step.resolved.scoreGained
                     │          await animatePops(...)
                     │          await animateMoves(...)
                     │          await animateSpawned(...)
                     ▼
                     useAppStore.addScore/decrementMove
                     ▼
                     если score ≥ target → scene='win'
                     если moves == 0   → scene='gameOver'
```

## Ключевые модули и их ответственность

| Модуль            | Ответственность                                                                | Не делает                            |
| ----------------- | ------------------------------------------------------------------------------ | ------------------------------------ |
| `Board`           | Хранит сетку тайлов, операции `swap/remove/collapse/refill`.                   | Не знает про рендер и анимации.      |
| `matchFinder`     | Чистая функция поиска совпадений и крестов.                                    | Не модифицирует доску.               |
| `cascade`         | Шаг каскада: матчи → удаление → коллапс → спавн.                               | Не анимирует.                        |
| `gameMachine`     | Допустимые переходы между фазами игры.                                         | Не выполняет сами действия.          |
| `CommandQueue`    | Последовательно гоняет асинхронные команды.                                    | Не знает про содержимое команд.      |
| `BoardController` | Связывает Pixi-объекты с моделью, выполняет анимации, оркеструет игровой цикл. | Не управляет UI-меню/модалками.      |
| `useAppStore`     | Глобальный UI-стейт (сцена, счёт, ходы, прогресс загрузки).                    | Не хранит игровую модель целиком.    |
| `bus` (mitt)      | Канал событий между слоями.                                                    | Не хранит состояние.                 |
| `PhysicsWorld`    | Обёртка над Matter.Engine, шаг физики.                                         | Не привязана к конкретным сущностям. |

## Расширения, которые ложатся естественно

- **Бустеры**: добавляем `Tile.type = 'bomb'` и логику в `matchFinder`/`cascade`.
- **Уровни и цели**: новый модуль `rules/levels.ts`, JSON-конфиги.
- **Сохранение прогресса**: middleware в `useAppStore` (zustand `persist`).
- **Аналитика**: подписка на `bus` — отправка событий в Amplitude/PostHog.
- **Сетевая синхронизация**: общий `EventBus` поверх WebSocket.
- **Редактор уровней**: отдельная React-страница, переиспользует `Board`.

## Антипаттерны (как НЕ делать)

- Хранить позиции тайлов в React state и пересчитывать каждый кадр —
  это убьёт производительность из-за реконсиляции.
- Анимировать Pixi-объекты через React: лучше держать tween-таргеты
  на refs или в контроллере.
- Запускать `Engine.update(Matter)` отдельным `requestAnimationFrame` —
  это рассинхронит физику и Pixi. Всегда тикайте через общий ticker.
- Загружать ассеты по одному в момент использования — пользователь увидит
  пустые сцены. Грузите бандлами через `Assets.loadBundle`.
