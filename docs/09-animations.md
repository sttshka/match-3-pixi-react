# 09. Анимации и интеграция с Pixi

В match-3 анимация — это не украшение, а **сама механика**. Игрок
ощущает удар комбо ровно в тот момент, когда экран “взрывается”
каскадом.

## Стек

- **GSAP** — основной tween-движок.
- Промисификация — `tweenTo(target, props)` возвращает `Promise<void>`.
- **CommandQueue** — последовательное выполнение анимационных шагов.
- **EventBus** — анимационные подсказки (звуки, частицы, скрин-шейк)
  реагируют через подписки.

## Базовые tween'ы

```ts
import { tweenTo, tweenAll } from '@utils/tween';

await tweenTo(sprite, { x: 100, y: 200, duration: 0.3 });
await tweenAll([
  { target: a, props: { x: 0, duration: 0.2 } },
  { target: b, props: { x: 0, duration: 0.2 } },
]);
```

GSAP принимает любые свойства, включая вложенные (`'scale.x'`). Мы
прокидываем `scale` как удобное “комбинированное” свойство в обёртке.

## Easing

Чтобы анимация ощущалась “живой”, используем разные кривые:

| Действие    | Ease           | Длительность                 |
| ----------- | -------------- | ---------------------------- |
| Своп        | `power2.inOut` | 0.22 с                       |
| Откат свопа | `power2.inOut` | 0.18 с                       |
| Поп (взрыв) | `back.in(1.6)` | 0.25 с (alpha→0, scale→1.35) |
| Падение     | `power1.in`    | 0.32 с                       |
| Спавн       | `bounce.out`   | 0.32 с                       |

## Последовательность каскадного шага

```
[matches found]
   │
   ▼
animatePops(removed)   ─ 0.25 с
   │ (alpha→0, scale→1.35, затем destroy)
   ▼
animateMoves(moves)    ─ 0.32 с
   │ (тайлы съезжают вниз по физике)
   ▼
animateSpawned(spawned)─ 0.32 с
   │ (новые тайлы прилетают сверху с bounce)
   ▼
[следующий шаг каскада или idle]
```

Каждый шаг — это `await` внутри `resolveCascades()`. Это даёт
**предсказуемый ритм**: даже если GSAP сделает анимацию длиннее
из-за пропуска кадра, следующая фаза начнётся ровно после.

## Сочетание с физикой

Если используете Matter.js для эффектов разлёта, физика тикает в
параллели с GSAP, но логика **ждёт только GSAP**. Это разделение
важное: физические осколки могут жить ещё секунду после того, как
каскад завершился — пользователь видит “отголосок”.

## Tweens и React реконсиляция

Если бы мы анимировали через React (меняли позицию через `setState`),
каждый tick вызывал бы перерендер. Это допустимо для 1-2 объектов,
но **неприемлемо** для 64 тайлов 60 раз в секунду.

Решение в шаблоне — анимировать **напрямую** на `DisplayObject` через
`gsap.to(...)`. React в этих анимациях не участвует — он только
показывает финальный результат через UI-стейт (счёт, ходы).

## Скрин-шейк

Простая, но эффектная анимация:

```ts
function shake(camera: Container, intensity = 6, duration = 0.25) {
  const t = gsap.timeline();
  const orig = { x: camera.x, y: camera.y };
  for (let i = 0; i < 6; i++) {
    t.to(camera, {
      x: orig.x + (Math.random() * 2 - 1) * intensity,
      y: orig.y + (Math.random() * 2 - 1) * intensity,
      duration: duration / 6,
      ease: 'sine.inOut',
    });
  }
  t.to(camera, { x: orig.x, y: orig.y, duration: 0.1 });
}
```

Привязывайте к крупным событиям: бустер сработал, длинный каскад
завершился.

## Подсказка ходов

Если игрок “думает” дольше 5 секунд — подсветите валидный ход:

```ts
gsap.to(tileView.scale, { x: 1.06, y: 1.06, yoyo: true, repeat: -1, duration: 0.4 });
```

Останавливайте при следующем pointerdown.

## Skeletal / Spine

Если будут полноценные арты с покадровкой — используйте `pixi-spine`.
В шаблоне это не подключено, но `BoardController` спроектирован так,
что view-объект можно заменить на `Spine` без переписывания логики.

## Производительность анимаций

- **Не плодите tween'ы.** Один `gsap.to(sprite, { x, y, duration })` лучше
  двух раздельных.
- **Используйте `overwrite: 'auto'`** в GSAP, чтобы при перезапуске
  анимации старый tween останавливался автоматически.
- **Killtweens на destroy.** При уничтожении контроллера —
  `gsap.killTweensOf(allTiles)`.
- **Снизьте `fps` на слабых устройствах.** `Ticker.maxFPS = 30` — резкое
  улучшение энергопотребления.

## Чек-лист для нового действия

1. Описать, **какие** свойства Pixi-объекта меняются.
2. Подобрать длительность и easing.
3. Завернуть в `tweenTo` / `tweenAll`.
4. Положить в `CommandQueue`, если требуется последовательность.
5. Эмитить событие в `bus` — пусть звук/частицы реагируют независимо.
