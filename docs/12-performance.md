# 12. Производительность

Match-3 на современных устройствах должен идти 60 FPS без проблем
даже без оптимизаций. Но как только появятся частицы, фильтры,
большие доски (10×12), физика — начинаются нюансы. Здесь — самое важное.

## Профилирование

1. **DevTools → Performance**. Запишите 5-10 секунд активной игры с
   каскадами. Смотрите на:
   - Зелёные “Painting/Composite” — Pixi-рендер.
   - Жёлтые “Scripting” — ваша логика.
   - Фиолетовые “Rendering” — стили DOM-оверлея.
2. **GPU**: вкладка Layers / Performance Monitor.
3. **Pixi Stats** — добавьте `pixi-stats` в dev-режиме, чтобы видеть
   draw-calls и количество спрайтов.

## Топ-7 оптимизаций

### 1. Спрайт-атласы

Каждая отдельная текстура — отдельный `BindTexture` вызов. Атлас
с 30 фреймами рисуется как один draw call.

### 2. `ParticleContainer`

Для массовых эффектов (искры, частицы):

```ts
const particles = new ParticleContainer({
  maxSize: 1000,
  properties: { position: true, alpha: true, scale: false, rotation: true, color: true },
});
```

Запрещены некоторые свойства, но draw calls сводятся к одному.

### 3. Не дёргайте `Graphics.clear()` каждый кадр

Если фигура не меняется — рисуйте один раз. Если меняется — лучше
заменить `Graphics` на `Sprite` с предрассчитанной текстурой.

### 4. Текстуры power-of-two

WebGL лучше работает с текстурами размеров 2^N × 2^M. Атлас 2048×1024
быстрее, чем 1024×900.

### 5. Не используйте `Filter` без причины

Каждый фильтр — это `RenderTexture` за кулисами. На мобильных
`BlurFilter(radius=20)` легко съедает 8 ms.

### 6. `roundPixels`

Включайте на `Application` или конкретных спрайтах, если позиции
плавающие — это уберёт “дрожание” и слегка ускорит композицию.

### 7. Снижайте `resolution`

`resolution = devicePixelRatio` отлично для retina, но на телефоне 3x
это в 9 раз больше пикселей чем 1x. Ограничивайте: `Math.min(dpr, 2)`.

## React-специфика

- **Селекторы Zustand**. `useAppStore(s => s.score)` обновляется только
  при изменении `score`. Не пишите `useAppStore()` — это вернёт весь
  стор и сделает компонент “красным”.
- **Мемоизация коллбеков**. `pixiGraphics.draw` пересоздаваемый каждый
  render будет вызывать перерисовку.
- **Списки**. Если у вас 64 React-компонента тайлов — оборачивайте в
  `React.memo` + ключи по `tile.id`.

## Канвас и DOM

DOM-оверлей (HUD, модалки) — это отдельные слои композиции. При большом
HUD’е (анимации, blur) их рендеринг тоже тратит фрейм-бюджет. На
слабых устройствах отключайте `backdrop-filter` (он у нас есть в стилях).

## Memory churn

- Не создавайте `Graphics` каждый кадр в `draw`. Заведите однажды и
  переиспользуйте.
- Не allocate'те массивы в `useTick` callback'е каждый тик. Заведите
  заранее буферы.
- Большие текстуры освобождайте через `Assets.unloadBundle` при смене
  уровня.

## Физика

- `Matter.Engine.update(engine, dt)` дешёвый при <100 телах.
- При >300 телах — fixed step + sleeping + `engine.constraintIterations`.
- При >1000 — рассмотрите Rapier.js (WASM).

## Worker-ы

`findMatches` — это микросекунды для 8×8. Но если доска 16×16, и матч-чекер
работает каждое нажатие хинта/каждые 100 ms — рассмотрите вынос в
Worker. Структура:

```
main thread        worker
   │ postMessage(board)
   ▼
   │                ──▶ findMatches(board)
   │                ◀── postMessage(matches)
   ▼
обновить view
```

## Бюджет 16.6 ms (60 FPS)

Ориентир для типичного кадра:

- 3-4 ms — JS логика (включая GSAP)
- 6-8 ms — Pixi render (draw calls + GPU)
- 2-3 ms — композиция и DOM
- остаток — запас

Если суммарно > 12 ms — пора профилировать.

## Чек-лист

- [ ] Используется атлас, а не отдельные PNG.
- [ ] `resolution` ограничен 2.
- [ ] Графика интерактивна через `eventMode: 'static'`, не `'dynamic'`.
- [ ] Фильтры применяются к маленьким контейнерам.
- [ ] Поп/фейд эффекты используют `ParticleContainer`.
- [ ] React-компоненты используют селекторы Zustand.
- [ ] При смене уровня — `Assets.unloadBundle`.
- [ ] GSAP-tweens корректно завершаются (`killTweensOf`).
