# 05. Best practices Pixi v8

Этот раздел — конспект-памятка. Включает то, что часто спрашивают в проектах
match-3 и других 2D-играх.

## Жизненный цикл

- **Используйте `await app.init(...)`.** В v8 инициализация `Application`
  асинхронна. `@pixi/react` делает это под капотом.
- **Один `Application` на страницу.** Множественные application'ы — это
  множественные WebGL-контексты, что плохо с точки зрения памяти и
  производительности.
- **Чистите за собой.** На размонтировании сцен — `controller.destroy()`,
  `physics.destroy()`, `texture.destroy()`. Spritesheet → `sheet.destroy(true)`.

## Контейнеры и сортировка

- Дробите сцену на **слои-контейнеры** (`gridLayer`, `tilesLayer`, `overlayLayer`)
  — это упрощает z-ordering без `sortableChildren`.
- Включайте `sortableChildren` только когда **нужно** менять порядок
  ребёнка через `zIndex`. Иначе включённая сортировка тратит CPU каждый кадр.

## Graphics v8

- Новый API основан на цепочках: `g.rect(x,y,w,h).fill({...}).stroke({...})`.
- Если фигура **никогда не меняется** — нарисуйте её один раз. Перерисовка
  `Graphics` каждый кадр аннулирует мешевый кэш.
- Если фигура меняется часто (например, прогресс-бар) — лучше `Sprite`
  с предрендеренной текстурой и менять `width`, или использовать
  `Mesh` с тайлинговой текстурой.

## Spritesheet и атласы

- Готовьте атласы заранее (TexturePacker, Spritesheet от Pixi, FreeTexPacker).
- Включайте `mipmap: 'on'` для текстур, которые рендерятся в разных
  масштабах — это убирает шум при уменьшении.
- Учитывайте `padding` между фреймами, чтобы не было “bleeding”.
- Используйте WebP/AVIF для уменьшения веса (но не KTX2 без поддержки
  во всех браузерах, если не используете compressed-textures).

## Текстуры и память

- `Texture.from(url)` кэширует — повторные вызовы вернут ту же текстуру.
- `texture.destroy(true)` — освобождает и base-texture.
- `RenderTexture` полезен для предрасчитанных эффектов (тени, маски,
  превью-аватарок). Не злоупотребляйте — это VRAM.

## Pixi Assets API

- Один `Assets.init({ manifest })` за приложение.
- Грузите **бандлами**: `Assets.loadBundle('preload')`, `Assets.loadBundle('level-1')`.
- В `manifest` можно указывать форматы по приоритету: WebP → PNG.
- Прогресс грузится callback'ом: `Assets.loadBundle('x', (p) => …)`.

## Event mode

В Pixi v8 интерактивность управляется через `eventMode`:

- `'auto'` — наследует от родителя (по умолчанию).
- `'none'` — не реагирует.
- `'passive'` — может быть hit-test'нут, но события не вызываются.
- `'static'` — обычные интерактивные объекты.
- `'dynamic'` — для объектов, у которых меняются позиции/размер каждый кадр
  и они должны корректно ловить ввод (дорого, но точно).

Для match-3 тайлов хватает `'static'`, потому что во время свопа
ввод заблокирован `CommandQueue.isBusy`.

## Hit area

- Стандартный `hitArea` доски — невидимый прямоугольник, который ловит
  все клики и через `toLocal` определяет ячейку. Это дешевле, чем
  делать каждый Graphics интерактивным.

## Resize, DPR, autoDensity

- `autoDensity: true` + `resolution: window.devicePixelRatio` даёт
  чёткую графику на retina. Ограничивайте `resolution` максимумом 2,
  чтобы не убить FPS на 3x экранах.
- На размер канваса полагайтесь на `Application` (через `<Application width=... />`).

## Render hints

- `roundPixels: true` в `Application` или на спрайте устраняет
  субпиксельные “плавающие” позиции у спрайтов с jitter.
- `cullable = true` на контейнере включает встроенный culling — Pixi
  пропустит отрисовку детей, находящихся за пределами viewport.

## ParticleContainer

- Используется для **массовых одинаковых** спрайтов (одна base texture).
- Очень быстрый, но имеет ограничения: нельзя менять некоторые свойства
  спрайтов индивидуально (зависит от флагов конструктора).
- Идеален для эффектов взрыва тайла, дождя, искр.

## Pixi и WebGPU

- В v8 можно указать `preference: 'webgpu'`. Если браузер не поддерживает —
  Pixi откатится на WebGL2.
- В debug-режиме `preference: 'webgl'` помогает локализовать визуальные баги.

## Filters

- Используйте экономно. Каждый фильтр — это `RenderTexture` за кулисами.
- На мобильных тяжёлые фильтры (например, `BlurFilter` с большим radius)
  легко съедают 5-10 ms на кадр.
- Применяйте фильтр к **самому маленькому** контейнеру, к которому он
  логически относится.

## Color и tinting

- Спрайт с одним атласом + `tint` это самый дешёвый способ дать вариации
  цвета. Не делайте по текстуре на каждый цвет.

## Текст

- Если текст не меняется часто — `Text` подходит.
- Если меняется каждый кадр (счёт во время каскада) — используйте
  `BitmapText` (билд из bitmap-font'а, не дорогой по CPU).
- Не пересоздавайте `Text` каждый кадр — модифицируйте `text` поле.

## Memory leaks: чек-лист

- Все слушатели снимаются в `destroy()`?
- Все `Texture.from` ассеты освобождаются (`Assets.unload(...)`) при уходе со сцены?
- Не остаются ли ссылки на удалённые `DisplayObject` (например, в Map)?
- Pixi `Container.destroy({ children: true, texture: false })` для удаления
  поддеревьев.
